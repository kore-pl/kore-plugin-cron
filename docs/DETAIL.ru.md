# Плагин планировщика задач（kore-plugin-cron）

## Обзор

Этот плагин производственного уровня реально управляет crontab текущего пользователя: все чтения и записи идут через `crontab -l` / `crontab -`, без прямого изменения `/var/spool/cron`; плагин не содержит планировщика, тикера и опроса (G-19) — фактический запуск выполняет системный cron. Границы (ADR-0019): он управляет только системным crontab (задачи shell / http); задачи типа «вызвать метод плагина по расписанию» относятся к планировщику ядра, плагин лишь формирует рекомендованное описание, не создавая и не выполняя их.

## Поверхность протокола

Протокол `kore.plugin.v1`, `lifecycle=lazy`. Методы: `kore.ping` / `shutdown` / `reload` и `cron.list` / `add` / `remove` / `replace` / `disable` / `enable` / `logs` / `runlog` / `run` / `templates` / `batch` / `migrate` / `config.get` / `config.set`. `cron.runlog` — журнал выполнений только для чтения, `limit` по умолчанию 50, максимум 200; `cron.batch` обрабатывает не более 50 записей за вызов без отката при частичном сбое; `cron.migrate` переписывает строки-обёртки, указывающие на каталоги версий, на стабильный путь и объявлен как `post_upgrade`.

## Основные возможности

Каждая запись резервируется и переписывается целиком; отключение сохраняет исходное определение, добавляя лишь комментарий-метку, а включение восстанавливает его дословно; `cron.logs` читает журналы запуска системного cron (journalctl / cron.log / syslog); `cron.runlog` пополняется `cron.run` и обёрткой `__task-run` в `<state>/runlog/runlog.jsonl`, при запросе читается только конец файла, без фоновых сборщиков, сохраняются первые 512 байт и выставляется `truncated`. Четыре опции конфигурации — `backup_dir` / `runlog_dir` / `log_file` / `disable_journal` — при сохранении записываются обратно в переменные `KORE_CRON_*` для немедленного эффекта.

## Граница безопасности

Плагин управляет только системным crontab и только строками задач, которые он создал; нераспознанные строки сохраняются как есть и учитываются с предупреждением; перед записью деструктивных операций создаётся резервная копия. Задачи типа плагин никогда не выполняются самим плагином — они передаются планировщику ядра, чтобы не получать прав сверх объявленной области; `cron.run` выполняет только команды уже зарегистрированных задач. Возможности: `system:read` (чтение) и `system:admin` (запись). Обход интерфейса crontab путём прямого изменения каталога spool находится вне поддерживаемой области и является ограничением среды.

## Сборка и проверка

Ежедневная проверка — локальный `make check` (gofmt → go vet → go test -timeout 200s); перед выпуском `make dist` дважды с совпадающим sha256. GitHub Actions только вручную, Gitea Actions по тегам версий. Уровень глубины `production`; контрактные тесты новых методов, таких как `cron.runlog`, выполняются вместе с обычным контролем.
